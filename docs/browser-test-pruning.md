# 浏览器回归精简审计

目标不是把长文件拆成更多文件，而是减少不增加覆盖的真实浏览器工作量，消除靠睡眠猜测状态的竞态。不能通过延长断言 timeout、静默 skip 或重试变绿掩盖问题。

## 本轮处理

| 原检查 | 处理 | 保留的保障 |
| --- | --- | --- |
| 每个测试的服务器退出最多空等 10 秒，随后未检查线程 | 测试宿主限定退出宽限期，取消残留 SSE；检查线程确实退出 | 不改运行中请求或产品服务器设置；独立长连接测试证明退出取消完成 |
| 级联：3 页面形态 × 3 宽度 | 完整看板缩为最窄宽度下的 3 种形态 | 375/894/1440 的真实定位与行高由组件测试覆盖；server/share/html 保留状态、边界与全选契约 |
| 两个导出级联重复测搜索行高 | 保留两个独立菜单可操作及导出容器圆角、溢出；行高只在组件层测 | 没有删除导出特有的包装层缺陷回归 |
| Plotly 每种图 18 次点击排列 | 6 次代表操作，覆盖四个值、返回旧值、三档间隔与三档鼠标位移 | 动作不丢失、不重复、顺序、revision、最终过滤及高亮；移除没有产品契约的“实际间隔不得多出 500ms”性能门槛 |
| 迟到查询失败依赖 700ms/900ms 两个计时器 | 用可释放 Promise 在新结果出现后明确释放旧失败 | 旧失败不得覆盖新选项、ready 状态和诊断 |
| 级联更新、Plotly 滚轮固定睡眠 | 等待实际渲染调用／滚动位置变化 | 同级 View 不被误刷、页面滚动不修改坐标范围 |
| Perspective 连续三次同样释放恢复，先睡 300ms | 两次生命周期，等待 ready/可见状态 | 首次和再次释放资源计数相等，恢复可继续使用；不是删掉重复生命周期保障 |
| Perspective 恢复设置时反复调用 restore 直到超时 | 只调用一次 restore 并 await flush，读取结果 | 不再靠重复操作覆盖丢失更新 |
| Gallery 500 多行全交互在三种形态重复 | 完整交互只在服务端执行；share/html 分别检查所有控件已 hydrate、选择同步、真实自定义 View 与千选项资产 | 跨形态打包和状态仍覆盖；组件细节不重放三遍 |
| 分析 CLI 和 visual-check 在三引擎分组重复启动 Chromium | 9 项只在 Chromium 分组执行 | 原 CLI 断言完整保留；Firefox/WebKit 真正使用自身引擎的 UI 与证据测试不受影响 |
| 单看板 Plotly／级联用例复制并加载整个 feature-showcase | fixture 显式只复制目标看板目录，保留 workspace、adapter、资源 | 不改变被测看板内部的多图联动；未知目录直接报错，不默默漏掉目标 |

## 证据和边界

- 历史日志里的 WebKit Plotly 框选／套索失败涉及真实手势及并行图表初始化，不应因为曾失败而删除。两种手势仍保留真实鼠标和中途创建兄弟图表回归，本轮三浏览器各通过 4 项点击／拖选定向检查。
- 历史多输入框与远程查询失败是有价值的状态回归，保留；表格排序焦点的局部行为已在上一轮下沉到组件层。
- SSE 独立复现：旧实现 10.59 秒失败；修正后与迁移检查共 4 项在 1.16 秒通过。相同核心 16 项每引擎由 238～248 秒降为 107～120 秒，无重试。
- Gallery 新便携检查初版误读了包 adapter 注册表，失败立即指向测试自身。改为检查组件实际 hydrate 状态后，只重跑两项便携检查，三引擎通过；首次失败日志保留在 `deep-trim-gallery/`。
- 测试开发日志位于 `.test-evidence/deep-trim-*`；每次运行独立目录，完整矩阵日志为 `deep-trim-final/`。具体通过数量和剩余范围以实际 summary/log 为准。
- 完整矩阵的 Firefox 出现三项失败，没有重跑整套：Gallery 顺序巡检仅检查本地 checkbox 数量就开始下一次操作，现明确等待已提交状态；连续清空／恢复的组件行为移至无服务器的小页面。Perspective 空状态用例先明确建立单项选择再清空，不夹带三个连续点击；恢复用例等待非空的新 frame ID、对应文档身份及实例创建，避免把过渡空 ID 当成恢复完成。原始失败 trace 全部保留。
- 初次矩阵（最终小修前）：Chromium 124 项通过、493.70 秒；WebKit 115 项通过、500.07 秒；Firefox 112 项通过、3 项失败、606.30 秒。不能称为“首次矩阵全绿”。后续目标文件 19 项三浏览器均通过；Perspective 两项和新增 checkbox 小测试另行定向验证。
- 最终定向结果：`deep-trim-final-affected/` 三引擎各 19 项通过（120～139 秒）；`deep-trim-perspective-state-fixed/` 各 2 项通过（9～11 秒）；`deep-trim-checkbox-restore/` 检查最终清空再恢复行为。没有为处理上述三项失败而重跑整个矩阵。
- 精简完成时收集为 Chromium 125、Firefox/WebKit 各 116：原 120 项中的有价值回归仍有对应覆盖，部分重型排列删除后新增了更细的组件用例，因此不能用函数数直接衡量成本。重型层矩阵执行数从原来的 360 减至 318，另有 39 次轻量组件执行；更大的节省来自消除服务器退出空等和冗长交互重放。
- 后续针对 Firefox 丢点击新增 3 项确定性组件回归，彼时 Chromium 128、Firefox/WebKit 各 119，组件层 16 项；没有增加长链路排列。原因与验证见 [checkbox-sync-regression.md](checkbox-sync-regression.md)。
- 异步生命周期专项再增加 18 项组件回归，组件层 34 项；现有保存链路加入可控宿主握手，不增加长链路排列。专项范围和分阶段验证见 [async-lifecycle-workstream.md](async-lifecycle-workstream.md)。
- 保留真正验证 timeout/cancellation 的故障注入，也保留真实手势中用于模拟点击间隔的时间。不能机械删除所有含 timeout 的代码；应删除没有状态或行为依据的等待。

## 后续改动规则

1. 新增宽度／页面／浏览器参数化，必须说明新增了哪一种不同故障边界，避免笛卡尔积。
2. 某条失败先看 trace 和状态。若只改该用例，定向运行；只有共享基础设施改变才扩大验证。
3. `summary.json` 的每个 result 记录该引擎实际命令。Firefox/WebKit 分组明确不含固定 Chromium 的 CLI 测试，不能将单跑这些分组表述为完整 CLI 验证。
4. 单次通过不是“零偶发”的证明。保留失败记录，不通过自动重试计算更漂亮的成功率。
